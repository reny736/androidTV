# 平板投屏 0.2.2

用于小米平板 7 / Android 16 的极简 DLNA MediaRenderer 测试版。原生 Android 界面，Media3 ExoPlayer 播放 HTTP(S)、HLS、DASH 媒体，SSDP 设备发现，SOAP 控制和 GENA 状态通知。无账号、广告和分析服务。

[第二版测试 APK](dist/TabletCast-0.2.2.apk) · [安装说明](#安装与测试) · [SHA-256 校验](dist/TabletCast-0.2.2.apk.sha256)

## 第二版界面

- 仅允许两个相差 180° 的横屏方向，默认设备名为 `AndroidTV`；从第一版升级会迁移旧默认名，保留自定义名称。
- 主界面左侧 75% 由播放器通高铺满，右侧 25% 为功能区。没有播放器外的白色留边；视频保留原始比例，比例不同时使用播放器内的黑色留边，避免拉伸。
- 功能区提供设备名称修改、全屏、播放/暂停、前后跳转 15 秒、进度、音量、停止和重新发现设备。名称修改按钮为纯文字“修改”。
- 接收视频后默认继续分栏播放；点击全屏隐藏右侧，轻触视频显示控制条，返回键退出全屏。
- 原生液态玻璃风格：深色柔焦背景、烟灰透明材质、冷暖高光边缘与乳白激活按钮。材质为 Android 原生绘制的视觉近似，不读取视频帧制作实时背景模糊。
- 音量和分栏/全屏进度条均为细玻璃胶囊，保留原生 SeekBar 的拖动、键盘与无障碍语义；按住平滑放大到 1.10 倍，松开或取消时阻尼回弹。拖动进度时预览目标时间，松开跳转，取消拖动不跳转。系统关闭动画时直接切换状态。
- 面板在较小窗口下可滚动；进度和跳转在直播等不可拖动的媒体中禁用。

## 0.2.2 音量修复

- 移除滑条继承的系统按压背景，消除拖动时多余的白色圆形，保留玻璃胶囊和回弹动画。
- 界面及 DLNA 音量、静音统一控制设备媒体音量；固定音量设备回退到播放器增益。音量键控制媒体流，界面定期同步实际音量，拖动期间避免刷新覆盖。
- 已通过构建、单元测试、Android Lint、APK 签名验证及 Android 16 模拟器手势回归，检查拖动、静音、最大音量和按压外观。

## 核心结构

- `MainActivity.java`：原生 Android 界面、Media3 播放、错误提示与生命周期管理。
- `CastLayout.java` / `StageGeometry.java`：通高的 75% / 25% 分栏和全屏切换。
- `GlassUi.java`：原生玻璃材质、背景和播放器图标。
- `LiquidSlider.java`：共享的细玻璃音量/进度条与触摸回弹动画。
- `DlnaServer.java`：SSDP 发现、设备描述、SOAP 播放控制和 GENA 状态通知。
- `ServiceDescription.java`：生成三个 UPnP 服务的能力描述。
- `app/src/main/java/fi/iki/elonen/NanoHTTPD.java`：内置 HTTP 服务，补齐 DLNA 订阅方法支持。
- `app/src/test/`：UPnP 服务描述的单元测试。
- `dist/`：已测试的 APK 和校验文件。

实现语言为 Java，最低 Android 8.0，目标 SDK 35。构建工具、SDK、模拟器镜像、签名密钥和运行日志均不纳入仓库。

## 安装与测试

1. 将 `dist/TabletCast-0.2.2.apk` 传到平板，允许文件管理器安装此来源的应用，安装并打开“平板投屏”。第二版沿用第一版的应用 ID 和本机调试签名，可覆盖升级。
2. 手机和平板连接同一路由器的局域网；不要使用访客隔离网络。高码率建议信号良好的 5GHz Wi-Fi。
3. 保持 APK 在前台。在手机咪咕视频 / 哔哩哔哩的视频播放器里点击投电视，选择“AndroidTV”，或右侧功能区中显示的自定义名称。点击“修改”可更改名称。
4. 测试开始播放、暂停、拖动、切换视频、结束投屏。分别测试普通视频、直播和会员视频，记录差异。
5. 在手机支持的情况下选择高清档位，持续播放至少 20 分钟，观察缓冲、掉帧和音画同步。没有真实片源测量前不宣称 4K 或某个码率已经通过。

搜不到设备：确认同网、平板前台运行、关闭路由器 AP 隔离，点击“重新等待投屏”。重连 Wi-Fi 会重新启动发现服务。

搜得到但播放失败：记录手机 App 版本、视频类别、选定清晰度、界面提示及是否所有视频都失败。详细错误码会写入 TabletCast 日志。带鉴权、DRM 或平台专属投屏协议的内容可能无法播放。

## 范围

- 直接播放手机提供的媒体地址，不转码，不人为设定清晰度上限。实际画质由下发片源、设备解码能力和网络决定。
- 不是屏幕镜像、AirPlay 或 Google Cast 接收器，不绕过会员与 DRM。
- 无后台常驻或开机自启，测试时请保持应用前台。
- 测试版 target SDK 35，可安装于 Android 16；未启用 Android 16 可选的本地网络保护测试模式。未来提升 target SDK 时需重新评估本地网络权限。
- 调试签名 APK 仅供本地安装测试；正式发布前需独立发布签名、完整第三方许可证及实机兼容验证。
- 请求头鉴权透传和高级 DLNA 功能尚未实现。

## 验证情况

0.2.2 的设备级手势检查位于 `app/src/androidTest/`，验证音量及分栏/全屏进度条的10%放大、回弹、实际音量/跳转、进度预览、取消拖动、固定触摸区域及无障碍范围。可构建 `assembleDebugAndroidTest`，将本地30秒测试视频推送到目标应用外部文件目录的 `gesture-demo.mp4`，再运行 `cn.tabletcast.test/cn.tabletcast.GlassGestureInstrumentation`；测试包不包含在交付 APK 内。

已在 Android 16 模拟器中通过横竖屏、设备改名对话框、基础视频播放、播放控制、状态订阅通知和错误页面检查；构建、协议描述单元测试、Android Lint 和 APK 签名验证通过。真实手机的 SSDP 发现、咪咕与哔哩哔哩平台兼容性及高码率性能仍需真机验证。

## 构建

Windows PowerShell 执行 `setup-tools.ps1` 下载项目内 JDK 17、Gradle 8.13 和 Android 命令行工具，然后执行 `build-apk.ps1` 安装 SDK 35、下载依赖、构建、运行协议描述单元测试、Lint 并验证 APK 签名。所有工具缓存保存在 `.tools`，首次构建需要网络。
